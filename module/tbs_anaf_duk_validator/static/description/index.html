ANAF DUKIntegrator

Validates Romanian ANAF tax declaration XML (D100, D101, D112, D205, D300, D394) with DUKIntegrator — the same official Java validator ANAF itself uses — running on your own server. Give it an XML string and a declaration code, get back a pass/fail verdict and, on success, the confirmation PDF DUKIntegrator produces. No HTTP relay, no vendor account, no per-validation fee.

●
The official tool, not a lookalike

Runs ANAF's own DUKIntegrator jar — the identical check your declaration goes through at SPV, run locally before you upload.

●
Self-hosted, no vendor lock-in

You install DUKIntegrator once, on your own server. No relay service, no API key, no subscription, no per-validation cost.

●
One service, any declaration module

Feed it an XML string and a declaration code — it does not care how the XML was generated or by which module.

What it does

Validate

Runs DUKIntegrator against your XML and a declaration code (D100, D101, D112, D205, D300, D394); returns a clear pass/fail verdict with the exact error text on failure.

Generate confirmation PDF

On a passing validation, also returns DUKIntegrator's own flat confirmation PDF for the declaration.

Self-service settings

A Settings page field for the DUKIntegrator installation path, plus a Check Installation button — confirm your setup without server or log access.

How it works

1

Install DUKIntegrator
The .jar files ANAF distributes, on your own server.

2

Set the path
Settings > General Settings > ANAF DUKIntegrator. Defaults to /var/odoo/dukintegrator.

3

Call the service
From any module: env['anaf.duk.validator'].validate(xml, code).

4

Get the verdict
Pass/fail, error text on failure, confirmation PDF on success.

External services

Runs on your server, talks to nothing else

This module requires a Java runtime and the DUKIntegrator .jar files on the Odoo server — ANAF's own validation tool, distributed by ANAF as part of its declaration-software tooling and not included with this module. It runs entirely as a local subprocess call; the XML you pass in never leaves your server.

This is different from validators that relay your declaration to a hosted HTTP service over the internet: nothing here talks to any TBS server, or any third party, at any point.

Frequently asked questions

Does this generate declaration XML?

No. It only validates XML you already have. Pair it with a declaration-generation module — TBS's own Romania Tax Declarations wires directly into it, and any other module can call the same service.

Does it need Odoo Enterprise?

No. It depends only on Odoo's base module and installs on Community or Enterprise.

What happens if DUKIntegrator is not installed yet?

You get a clear error naming the exact path checked, plus a Check Installation button in Settings so you can confirm your setup works before relying on it in a real declaration.

Where do I get the DUKIntegrator .jar files?

ANAF distributes them as part of its declaration-validation tooling. They are not redistributed with this module — search ANAF's site for "DUKIntegrator", or ask your accounting-software vendor, as most Romanian tools that submit to SPV already bundle a copy.

Is my declaration data sent anywhere?

No. Validation runs as a local subprocess call to the jar on your own server. Nothing is sent to TBS or to any third party.
